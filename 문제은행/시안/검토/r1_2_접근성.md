# 문제은행 시안 v5 접근성 점검 (WCAG 2.2 AA / K-WCAG 2.2)

방법: CSS 변수 전수 추출 후 Python으로 상대 휘도 계산(반투명은 실제 배경에 합성). 코드 전체와 캡처(데스크톱_mine, 모바일_sheet 등)를 확인. 코드 검색 결과: `aria-*`, `role=`, `alt=`, `keydown`, `Escape`, `:focus`, `@media`, `outline` 규칙이 모두 0건.

## 2. 점수 (1~10)

- 대비: 6. 글자는 대부분 우수하나 테두리·막대·mark·태그·placeholder가 기준 미달.
- 키보드: 2. 핵심 조작이 div+onclick이고 포커스 표시·포커스 가두기·Esc가 전혀 없음.
- 의미 구조: 2. 랜드마크·aria·alt·aria-live 없음, 제목 계층도 불규칙.
- 글자·터치 크기: 4. 12px 글자 다수, ▲▼✕ 버튼이 약 14~20px, 모바일은 3열 고정이라 가로로 잘림.
- 전체: 3. 데모로는 보기 좋지만 키보드·스크린리더 사용자는 사실상 사용할 수 없음.

읽기 순서와 한국어: DOM 순서는 헤더 → 필터 → 카드 → 내 시험지로 논리적이며 양호. 다만 카드 머리가 "18번 / 2026년 9월 모평 (2027학년도) / 목적 / 연계 소재만 / 오답 5위 · 61.4%"처럼 조각난 span이라 스크린리더가 "오답 5위 점 61.4퍼센트"처럼 어색하게 읽을 수 있음. 카드를 `<article aria-labelledby>`로 묶고 제목은 "2026년 9월 모의평가 18번 목적", 오답률은 "오답률 5위, 61.4퍼센트"로 쓰기. "시안:" 안내 alert와 "▲▼"의 의미도 라벨로 보완.

고대비 모드 가능성: 색을 모두 CSS 변수로 쓰므로 변수 교체만으로 가능. 단 반투명 합성색(`--line`, `--accL` 등)과 `box-shadow`로 구분하는 부분은 Windows 강제 색상(forced-colors)에서 사라지므로 `@media (forced-colors:active){.card,.box,button,input{border:1px solid CanvasText}}`와 선택 상태에 `outline`(색 아닌 두께)을 더해야 함. `color-scheme:dark`는 이미 선언돼 있어 기본 컨트롤 렌더는 양호.

## 4. 잘 된 점

1. 본문·보조 글자 대비가 높고(14.2, 9.6, 6.3:1) 가독성 좋은 Noto Sans KR+Source Serif 조합, `lang="ko"`, `keep-all` 줄바꿈 지정.
2. 상태를 글자로도 표시하는 곳이 많음(담기 버튼 "✓ 담음", 오답 "5위·61.4%" 숫자, 연계 방식을 글자 태그로 표기), 그리고 시험지 이미지 외에 '글자로 보기' 대체본이 이미 있음.
3. 색을 전부 CSS 변수로 관리하고 `color-scheme:dark` 선언 → 테마·고대비 지원 비용이 낮음. 서랍 폭 `min(640px,96vw)`·모달 `94vw`로 좁은 화면 배려.

## 5. 가장 먼저 고칠 5개

1. #1 div/a 클릭 요소를 전부 button·a로 교체(키보드 사용 가능의 전제).
2. #2 `:focus-visible` 3px 노란 외곽선 추가.
3. #3 서랍·모달에 role=dialog, 포커스 이동·가두기·Esc·복귀.
4. #4 900px 이하 1열 반응형(모바일·200% 확대 리플로).
5. #5·#8·#12 이미지 alt, 입력 label, 아이콘 버튼 aria-label(스크린리더 이름 붙이기를 한 번에).

## 6. 테마 대안의 접근성 (밝은 종이 vs 어두운 테마)

비교 기준별 판단:

| 기준 | 밝은 종이 테마 | 어두운(칠판) 테마 | 유리한 쪽 |
|---|---|---|---|
| 대비비 달성 용이성 | 검정 계열 글자로 13:1 이상을 쉽게 달성, 색조 태그도 5.6:1 이상 확보 쉬움 | 밝은 글자는 높으나 채도 색(분홍·초록) 태그와 반투명 배경이 대비를 깎음(실측 4.24, 2.90) | 밝은 테마 |
| 시험지 이미지와의 일치 | 시험지 이미지가 흰 바탕이라 주변과 같은 톤, 눈부심 경계가 없음 | 짙은 초록 바탕 사이 흰 이미지가 밝게 튀어 눈부심(캡처 확인) | 밝은 테마 |
| 저시력(시력 저하, 백내장) | 일반적으로 밝은 배경+어두운 글자가 읽기 속도·정확도 우세, 확대 시 글자 두께 선명 | 광량이 낮은 환경에서 불리하지 않으나 밝은 글자가 번져 보이는 헤일레이션이 있음 | 밝은 테마 |
| 난독·난시 | 밝은 바탕 위 순백(#fff)이 눈부시므로 약간 따뜻한 크림색으로 낮추면 좋음 | 순백 글자 대비 과다 시 번짐. 현재 #f3f1e6로 이미 완화 | 둘 다 가능(순백·순흑 피하기) |
| 장시간 사용(밤·교실 어두운 환경) | 어두운 방에서는 눈부심 | 저조도·수업 준비 야간 작업에 편함 | 어두운 테마 |
| 인쇄물과의 일치 | 종이 출력물과 같은 모양(미리보기) | 인쇄 미리보기와 화면 색이 다름 | 밝은 테마 |

결론: 기본 테마는 밝은 종이 테마 쪽이 접근성 기준에 더 유리하고(특히 이 앱의 핵심 콘텐츠가 흰 시험지 이미지), 어두운 테마는 야간·눈부심 민감 사용자를 위한 선택지로 두는 것이 좋음. 사용자 선택(밝게/어둡게/시스템 따름)과 별도의 "고대비" 옵션을 두는 3단 구성을 권장.

색 규칙 요약:
- 두 테마 모두 순백/순흑은 쓰지 않음(밝은: 바탕 #f7f4ea, 어두운: #14241f). 고대비 모드에서만 순흑·순백 허용.
- 텍스트는 4.5:1 이상(보조 글자도 포함), 테두리·막대·체크박스는 3:1 이상. 카드 면 구분은 색 차이(1.1~1.5:1에 불과)에 의존하지 말고 `--line` 1px 테두리로.
- 반투명 변수(accL, topL 등)는 테마마다 불투명 값으로 미리 계산해 두거나, 합성 결과의 대비를 위 표처럼 검증한 뒤 사용.
- 포커스 링은 `--focus`(밝은: #0b5a9c, 어두운: #ffe266)로 테마별 분리, 두께 3px 이상.
- 시험지 이미지는 어두운 테마에서도 흰 바탕 그대로 두되, 둘레에 `outline:1px solid var(--line)`을 주고 `filter:brightness(.92)`로 눈부심을 낮춤. 이미지를 색 반전하지 않음(그림·수식 왜곡).
- 선택 저장은 `localStorage`(실패 시 시스템 설정 따름), 선택 컨트롤은 `<button aria-pressed>` 3개(밝게·어둡게·고대비)로 헤더에 상시 표시.
