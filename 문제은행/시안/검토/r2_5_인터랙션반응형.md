# r2_5 인터랙션·반응형·인쇄 흐름·성능 재점검 (시안 v6)

방법: 헤드리스 Chrome을 원격 제어(CDP)해 너비 1440·1280·1024·768·390·360에서 장면 7개씩(검색결과·내 시험지·서랍·첫 화면·변형·주문서·묶음 문항)을 직접 캡처해 눈으로 봤습니다. 390·360은 frame.html 대신 화면 크기 에뮬레이션(미디어 쿼리 정상 작동)으로 찍었습니다. 키보드·클릭은 실제 키 이벤트로 시험했고, 성능은 실시간 ms를 쟀습니다(상태는 매번 초기화). 시안 파일은 고치지 않았습니다.

## (5) 성능 설계, 규모 시험 결과

데이터를 3,105문항으로 부풀려 쟀습니다(교재 1,000은 아직 기출과 같은 표에 없음). 24개 그리기 6.7ms, 검색 1회 10.6ms, '더 보기' 클릭 4~6ms(카드 120개까지), 120카드에서 담기 1.4ms, 120개 모두 담기 12ms, 내 시험지 121줄 3.1ms. 스크롤 위치는 '더 보기' 후에도 그대로. 이미지는 `loading=lazy`로 120카드 중 60장만 먼저 받음. 남는 위험은 세 가지입니다. 첫째 N14 이미지 무게(120카드 전부 열면 약 24MB). 둘째 단일 HTML에 문항 데이터가 들어 있어(지금 1.25MB) 4,100문항이면 약 5MB, 시험별 JSON을 필요할 때만 읽어야 함. 셋째 24개씩 이어 붙이기라 3,105개를 훑으려면 130번 눌러야 하므로 필터가 필수고, 위 N8 안내가 중요합니다. 한글 입력 중에도 검색이 돌지만 150ms 디바운스와 노드 교체가 입력칸 밖이라 문제 없음.

## (6) 가장 먼저 고칠 3개

1. N1: 130%에서 `100vh` 계산과 구간 기준을 맞춥니다(인쇄 버튼·TOP15가 화면 밖으로 나가는 실제 결함, 교실 TV·큰 글씨 사용자 직격).
2. N2: 내 시험지·필터 시트에 닫기 ✕, Esc, 포커스 가두기(서랍과 같은 `trap()` 재사용).
3. N4+N5+인쇄 미리보기: 인쇄 설정을 상태로 저장하고 묶음 번호를 보여 준 뒤, 미리보기 자리를 만듭니다(인쇄 흐름 4점의 원인).
