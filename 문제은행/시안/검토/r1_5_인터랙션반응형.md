# r1_5 인터랙션·반응형·인쇄 흐름·성능 점검 (시안 v5)

확인 방법: 기존 캡처(데스크톱 1440, 모바일 390)와 제가 직접 찍은 캡처(1280, 1024, 768, 500 변형 창, 768 서랍)를 눈으로 봤고, `make_mockup_v5.py`의 CSS/JS를 읽었습니다. 헤드리스 Chrome은 가상 시간이라 ms 단위 성능은 재지 못했고, 개수·구조만 확인했습니다. 그 한계 때문에 성능 수치는 쓰지 않았습니다.

## (1) 너비별 레이아웃 점검 (직접 본 것만)

| 너비 | 상태 | 문제 |

## (2) 점수 (1~10)

- 반응형 **2**: `@media`가 코드에 0건. 3단 고정 폭(250/1fr/330)이라 768에서 이미 깨지고 390은 쓸 수 없음.
- 상호작용 피드백 **4**: 담기 토글은 되지만 호버·눌림·포커스가 거의 없고, 서랍은 Esc가 안 되고 담기 후 확인·되돌리기가 없음.
- 인쇄 흐름 **4**: 설정이 한 패널에 있어 개념은 좋지만 미리보기가 없고, ▲▼만 있고 쪽·문항 수 설정이 없음.
- 성능 설계 **5**: 이미지를 파일로 따로 두고 `loading=lazy`를 쓴 점은 좋음. 120개 일괄 그리기·키 입력마다 전체 다시 그리기·페이지 나누기 없음은 실제 규모에서 문제.
- 전체 **4**: 칠판 테마와 정보 구조는 좋은데, 반응형과 접근성(키보드)이 비어 있음.

## (4) 권장 반응형 구조

```
>=1280  [고르기 250] [카드 1fr, 2열] [내 시험지 330 고정]
>=1024  [고르기 접힘(칩 줄)] [카드 1~2열] [내 시험지 330]
 768    [위: 칩 줄(시험·유형·TOP15)]
        [카드 2열 ...........................]
        [하단 고정 막대: 내 시험지 5문항 ▸]  -> 오른쪽 서랍 360px
 390    [위: 로고 / 독해·듣기 / 🔍]
        [필터 칩 한 줄, 가로 스크롤]
        [카드 1열 ...]
        [하단 고정 막대: 5문항 ▸ 인쇄]  -> 아래 시트(전체 높이 90%)
```

- 필터는 '필터' 버튼으로 여는 왼쪽 서랍. 선택된 필터는 칩으로 카드 위에 남김.
- 인쇄 흐름(모든 너비): 담기 → 순서·쪽 정리(드래그, 문항 수) → 미리보기(쪽 이미지 넘기기) → 인쇄/PDF. 인쇄 단계는 큰 화면에서는 전체 화면 모달이 낫습니다.
- 수업 모드: 머리줄의 `A−/A+`로 150~200%, 1열 큰 카드, 왼쪽·오른쪽 패널 숨김, 서랍은 화면의 70% 폭.

## (5) 잘 된 점 3개

1. 서랍의 '시험지 원본/글자로 보기' 전환과 EBSi 선택지 막대, 연계 상자가 한 화면에 있어 문항 하나를 판단하기 쉬움(데스크톱·768 서랍 캡처).
2. 이미지는 파일로 따로 두고 `loading="lazy"`, 썸네일은 고정 높이 210px라 담기 후에도 스크롤 위치가 크게 흔들리지 않음(코드 확인). 1.2MB는 문항 글자 데이터 약 1MB(820건)이고 이미지가 아님.
3. 담은 문항·독해/듣기 구분·TOP15 개수가 내 시험지 머리에 요약되고, 독해↔듣기·기출↔교재를 오가도 `my`가 유지됨(코드 확인).

## (6) 가장 먼저 고칠 5개

1. #1 `@media` 두 개와 내 시험지를 서랍·하단 막대로 접기(태블릿·모바일을 쓸 수 있게 하는 최소 작업).
2. #5 담은 문항을 `localStorage`에 저장(교사가 새로고침 한 번에 잃는 가장 큰 손실).
3. #3·#4 Esc/포커스/뒷배경 + 담기 토스트·되돌리기(상호작용의 기본기).
4. #12·#13 드래그 순서 바꾸기, 묶음 문항 표시, 쪽 나누기·한 쪽 문항 수 설정, 미리보기(인쇄 흐름의 핵심).
5. #6·#7·#8 '더 보기'(120개씩), 검색 디바운스, 이벤트 위임(3,105문항 + 교재 1,000에서 대비).
