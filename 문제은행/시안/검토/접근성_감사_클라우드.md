# 문제은행 시안 접근성 감사 (클라우드, 2026-11-02)

대상: `python build.py --예시`로 만든 `예시_화면시안.html` (cloud-explain 브랜치 f1467f2, 예시자료의 가짜 지문만 사용).
도구: Playwright Chromium으로 장면 8개 × 너비 4개(1440·1024·768·390)를 열고, 브라우저 안에서 대비·글자 크기·누르는 곳 크기·접근 가능한 이름·가로 넘침을 계산했다. 키보드는 Playwright의 실제 키 입력(Tab, Shift 없음, Enter, Esc, 방향키)으로 시험했다.
기준: WCAG 2.2 AA, 그리고 이 프로젝트 정책(본문 15px 이상, 누르는 곳 모바일 44px·데스크톱 40px 이상).
제외: 인쇄 창의 '해설지' 출력은 사용자 요청(해설은 QR로 제공)에 따라 점검하지 않았다.

심각도: **높음** = 키보드·화면 읽기 사용자가 막히거나 화면을 쓸 수 없음 / **중간** = WCAG AA 미달이거나 정책 미달이 넓게 퍼짐 / **낮음** = 다듬기.

## 한눈에 보기 (먼저 고칠 5가지)

1. **닫힌 서랍에 Tab이 들어간다 (높음).** 모든 화면에서 페이지 끝의 Tab 4번이 화면 밖 서랍 버튼(시험지 원본·텍스트·닫기·시험지에 담기)으로 간다. 포커스가 보이지 않는 곳으로 사라진다.
2. **서랍과 인쇄 창에 포커스 가두기가 없다 (높음).** 서랍은 25번 Tab 중 16번, 인쇄 창은 45번 중 30번이 어두운 막 뒤의 페이지로 나갔다. (`aria-modal="true"`라고 선언했는데 실제로는 막지 않음.)
3. **1024px 이하에서 화면이 깨진다 (높음).** 반응형 규칙이 없다(`@media`는 인쇄용 하나뿐). 1024에서 문제 고르기의 검색창이 '내 시험지' 머리를 덮고 표 오른쪽 열(오답률·상세)이 잘린다. 768·390에서는 글자가 한 자씩 세로로 쪼개지고, 390 인쇄 창 미리보기는 폭 32px이다.
4. **내 시험지 목록의 ▲▼✕ 버튼 (높음).** 24×24px이고 ✕는 대비 1.48, ▲는 2.56(아이콘 버튼은 3:1 필요). '빼기' 버튼 6개의 이름이 모두 같다.
5. **15px 미만 글자와 40px 미만 버튼이 화면마다 있다 (중간).** 13~14px 글자가 장면마다 4~23곳, 12px 1곳(홈 '평가원' 배지). 데스크톱에서도 32px 이하 버튼(초기화, 서랍 닫기·탭, 인쇄 창 닫기)이 많다.

어두운 모드는 **아직 없다.** 시스템을 어두운 모드로 두어도 배경 `#f8fafc`, 글자 `#1e293b` 그대로다(`dark_home_1440.png`). 템플릿에 `dark:`나 `prefers-color-scheme` 규칙이 0개다. 그래서 어두운 모드 대비는 점검할 대상이 없었다.

잘 된 점: 열면 포커스가 '닫기'로, Esc로 닫으면 '인쇄 및 미리보기'로 돌아온다. `role=dialog`, `aria-modal`, `aria-labelledby=pmTitle`. 버튼 묶음에 `aria-pressed` 상태가 있다. 미리보기 영역은 `tabindex=0`, 이름 '시험지 미리보기'라 키보드로 스크롤된다. 쪽 번호가 `aria-live`(`#pvNow`)다.

## 확인한 것과 못한 것

**확인한 것 (실제로 측정)**
- 8장면 × 4너비 + 어두운 모드 2장, 스크린샷 37장.
- 대비: 화면에 보이는 모든 글자의 실제 계산 색으로 WCAG 비율 계산(반투명 배경 겹침 포함).
- 글자 크기, 누르는 곳 크기(체크박스는 label 크기 포함), 접근 가능한 이름(aria-label, labelledby, 글자, label, title).
- 키보드: 실제 Tab·Enter·Esc·→ 키 입력으로 홈(30단계), 문제 고르기(70), 서랍(25), 인쇄 창(45), 보관함(20), 시험 선택 열기(14)의 순서·포커스 표시·가두기·복귀.
- 콘솔 오류: 0개(아이콘 png 없음 제외).

**못한 것 (추정이거나 미확인)**
- 화면 읽기 프로그램(NVDA, VoiceOver, TalkBack)으로 실제 듣기.
- 200% 확대, 글자만 키우기, Windows 고대비(`forced-colors`) 모드.
- 실제 휴대폰·태블릿 터치. 390·768은 Chromium의 모바일 흉내(터치 켬)다.
- PDF 저장(window.print) 결과.
- 어두운 모드 대비: 기능이 없어서 점검 대상이 없음.
- 실제 DB(문항 수백 개)에서의 긴 목록·긴 시험 이름. 예시자료는 시험 1개, 문항 6개다.
- 글꼴: 클라우드에서 cdn.tailwindcss.com·cdnjs·jsdelivr가 막혀 있어 같은 버전의 Tailwind 3.4(미리 컴파일), qrcode-generator 1.4.4, Pretendard 1.3.9를 npm에서 받아 대신 넣었다. Noto Serif KR은 Google Fonts에서 정상으로 받았다. PC의 실제 CDN 화면과 글자 폭이 1~2px 다를 수 있다.
- 아이콘 png(`icons/`)가 저장소에 없어 아이콘이 빠진 상태로 측정했다. 아이콘이 들어가면 메뉴·카드 머리 폭이 조금 달라진다.

## 다시 돌리는 방법

`검토/클라우드_감사도구/`에 이번에 쓴 스크립트가 있다(앱 코드는 바꾸지 않음).
1. `npm i tailwindcss@3.4.17 qrcode-generator@1.4.4 pretendard@1.3.9 playwright`
2. `npx tailwindcss -i in.css -o tw.css` (설정의 content가 `예시_화면시안.html`)
3. `node run.js` → 장면별 숫자와 `result.json`, 스크린샷 / `node kb.js` → 키보드 시험

PC에서는 CDN이 열려 있으면 `h.js`의 가로채기 부분을 빼고 돌려도 된다.
