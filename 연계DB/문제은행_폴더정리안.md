아직 아무것도 옮기거나 지우지 않았습니다. 제이님 승인 뒤에 진행합니다.

`평가원 연계내역분석/` 아래:
- `기출/<시행연도.월>/` 시험 PDF 원본 14회(2022.06~2026.09), 원본이라 고치지 않음
- `교재/` 교재 PDF 16권(2025~2027학년도), 원본이라 고치지 않음
- `연계DB/` 작업 본체
  - `문항DB/` 3,295개 파일(422MB): 문항 이미지와 표(2024.06~2026.09 8회)
  - `수업자료/` 367개(81MB): 생성기, 문항 데이터, 완성본(HTML)
  - `자료/` 62개: 시험·교재 글자 파일
  - `작업/` 80개: 변환 스크립트, 캐시, 백업
  - `분석/`, `듣기재분석/`, `파일럿/`, `문항DB_시범/`, `인계/`
  - 루트에 CSV 5개, 매뉴얼과 진행상황 백업 파일 30여 개

## 문제

1. 새로 생길 것(10년치 기출 DB, 듣기 파일, 내 문항, 변형 문항, 문제은행 프로그램)이 들어갈 자리가 없다.
2. `연계DB/` 루트에 백업 파일이 많이 쌓여 있다.
3. 시행연도별 정리가 `기출/`(PDF)와 `문항DB/기출/`에서 따로 되어 있다.
4. 스크립트와 문서가 현재 경로를 직접 적고 있어서, 옮기면 만들기·검사·인계 도구가 깨질 수 있다(생성기, `인계/파일목록.tsv`, 매뉴얼, CLAUDE.md).

## 제안: 기존은 그대로 두고 새 자리를 만든다

기존 `연계DB/`는 옮기지 않는다(깨질 위험, 이미 검증된 인계 체계 보존). 새 작업은 `평가원 연계내역분석/문제은행/` 아래에서 시작한다.

```
문제은행/
  README.md                  이 폴더 설명(이어받는 사람용)
  DB/                        데이터(배포용에서는 통째로 제외)
    기출/<시행연도>/<시험>/   문항 1개 = 파일 1개(문항 ID), 시행연도·학년도 칸 포함
    듣기/<시험>/              문항별 mp3(17개), 전체 mp3 원본은 원본/에
    교재/                    교재 문항 DB(연계DB의 교재 DB를 연결)
    연계/                    연계 분석(연계DB_통합_전체문항.csv를 문항 ID로 잇는 표)
    내문항/                  제이님이 캡처로 가져온 문항
    변형/                    만든 변형 문항(상·중·하)과 검수 기록
    통계/                    EBSi 오답률 TOP15 등
  규격/                      유형별 출제 규격표
  프로그램/                  화면, 검색, 조립, 인쇄, 변형 기능, 배포 빌드
  배포/                      DB를 뺀 배포 버전 결과물
```

원본 PDF와 오디오는 `기출/`, `교재/`에 그대로 두고, 새 폴더는 거기서 읽어 만든 결과만 담는다(원본 복사본을 또 만들지 않는다).

## 기존 `연계DB/`에 대한 정리(작게, 안전하게)

- 그대로: `수업자료/`, `자료/`, `분석/`, 핵심 CSV, `인계/`, 매뉴얼, 진행상황.
- 루트의 `*_백업_*.md` 30여 개는 `연계DB/백업/` 한 곳으로 모은다(내용은 그대로, 삭제 없음). 모은 뒤 `인계/파일목록.tsv`를 다시 만들어 이상 없음을 확인한다.
- `문항DB_시범/`, `파일럿/`은 `연계DB/참고/`로 모은다.

## 진행 순서

1. 이 정리안 승인.
2. `문제은행/` 빈 구조와 README 만들기(기존 파일은 건드리지 않음).
3. 백업 파일 모으기 전에 목록을 보여 드리고 승인받은 뒤 이동, 파일 확인 도구로 검증.
4. 10년치 원본 파일을 `기출/`에 시행연도별로 받는다(제이님이 찾으시는 것과 EBSi에서 받는 것).
