# 연계DB 프로젝트: 이어받는 Claude에게

> **2026-10-28 폴더 정리**: 루트의 `…_백업_…` 사본 30개는 `백업/`으로, `문항DB_시범`과 `파일럿`은 `참고/`로 옮겼다(내용은 그대로). 문서 속 옛 경로는 그 폴더에서 찾는다.

평가원 영어 모의평가·수능(2024.06 ~ 2026.09, 8회)의 EBS 연계를 분석해서, 기출 DB, 교재 DB, 연계 분석 수업 자료(HTML), 변형 문제, 수능형 모의고사와 "나만의 문제은행"(가칭)을 만드는 프로젝트입니다. 제이님(교사)이 이끌고 있습니다. Claude 계정이 바뀌어도 이 폴더만 있으면 이어서 할 수 있게 2026-10-23에 정리했고, 2026-10-26에 현재 상태까지 다시 저장했습니다. 이 파일은 바뀌지 않는 규칙과 안내만 적고, 지금 상태는 `진행상황.md`가 기준입니다.

## 먼저 읽을 것 (이 순서로)

1. `진행상황.md` 맨 위: 지금 어디까지 했고 무엇이 남았는지.
2. `연계DB_운영매뉴얼.md`의 0장(한눈에), 7.1절(협업 규칙), 8장(제이님 확인을 기다리는 것). 규칙은 이 문서가 기준이고, `진행상황.md`와 다르면 이 문서가 맞습니다.
3. 수업자료를 만지는 일이면 `수업자료/생성기/README.md`.
4. 다른 계정에서 이어받는 중이면 `인계/README.md`(이전 계정에서만 열리던 것, 대화 기록, 폴더 확인 방법).

읽은 뒤 제이님께 "지금 상태는 이렇고 이것부터 하겠습니다"를 두세 줄로 말하고 시작하세요. 제이님 확인이 필요한 것은 8장에서 골라 한 번에 여쭙니다.

## 제이님과 일하는 규칙 (제이님이 정한 것)

- 쉬운 말로, 결과부터 말합니다. 어려운 용어는 풀어 쓰고 존댓말을 씁니다.
- 큰 변경(눈에 보이는 디자인, 구조, 규칙)은 시안이나 아이디어를 먼저 보여 드리고 승인받은 뒤에 합니다. 작은 수정은 바로 하고 알립니다.
- 기존 파일은 덮어쓰지 않습니다. 바꾸기 전에 사본(`…_백업_*`)을 남깁니다.
- 확인한 것만 말합니다. 일부만 열어 봤으면 그렇게 쓰고, 못 본 것은 못 봤다고 씁니다.
- 수업자료는 칠판 화면 하나만 씁니다(밝은 기본 화면은 없앴습니다).
- 연계 문항(CSV에서 비연계가 아닌 행)은 "넣을지 말지"를 묻지 않고 넣습니다(제이님 2026-10-24). 한 지문 다문항(43~45번)은 43번 하나로 만들고 `covers` 로 44·45번을 맡깁니다(2026-10-26).
- 토큰이 많이 드는 일(새 회차를 에이전트로 만들기: 회차당 약 70~80만 토큰)은 시작 전에 비용을 알리고 방식을 제이님께 여쭙습니다. 이미 만든 회차를 틀 수정 뒤 다시 만드는 일은 거의 토큰이 들지 않습니다(프로그램이 돎).
- 화면이 이상하다는 지적(글자가 작다, 박스가 겹친다)을 받으면 먼저 `수업자료/생성기/tools/dev/measure_deck.py` 로 숫자를 재서 원인을 찾고, 눈에 보이는 바뀜은 시안(새 파일)으로 먼저 보여 드린 뒤 틀에 반영합니다. 틀을 고치면 기준 결과물(golden)을 `--update-golden` 으로 새로 쓰고 시험 64건을 돌립니다.
- 두 계정이 같은 시각에 이 폴더를 고치지 않습니다. 일을 마치면 `진행상황.md` 맨 위 "현재 상태"를 고칩니다.
- **GitHub에는 올리지 않습니다.** 제이님이 "아직 github엔 올리지 말아줘"(2026-10-23)라고 했습니다. 저장소를 만들거나 연결하지 않고, 계정 전체에 닿는 GitHub 도구도 쓰지 않습니다. 공개 범위는 C(전부 비공개)로 정했습니다.
- 전체 첫 화면의 회차 탭은 최근 회차가 왼쪽에 오고, 문항은 번호순입니다. 독립 출제 문항(연계되지 않은 문항)은 문항 장을 만들지 않습니다.
- 자료 규칙: EBSi 연계표는 공식 자료라 틀렸다고 단정하지 않고, 표에 없는 문항은 비연계입니다. 연계는 소재와 상황이 겹치는 간접 연계가 대부분이고 지문을 그대로 쓴 연계는 없습니다. 학년도는 시행 연도 + 1입니다.
- 일을 마치면 PC 폴더에 저장하고 `진행상황.md`를 갱신합니다. Claude 계정에서만 열리는 것(Artifact, Claude 문서)을 만들면 내용을 PC에도 저장합니다(`인계/게시한_문서/`).

## 작업 환경 (2026-10-23에 확인한 것)

- 2026-10-26에 확인: PC의 Windows Python 3.12(`python -X utf8 -I`), Node 24, PC 크롬(헤드리스, 임시 프로필), Tesseract(영어)로 후보 검사·숫자 재기·OCR·HTML 만들기가 된다. Playwright가 없어 자동 검사·PDF만 클라우드 세션 몫이다.
- PC는 Windows이고, Claude 데스크톱 앱에 `평가원 연계내역분석` 폴더를 연결해서 씁니다. 앱 안의 리눅스 VM에서는 `$HOME/mnt/평가원 연계내역분석/연계DB`로 보입니다. VM에는 Python 3.10, Node 22, git이 있고 크롬을 자동으로 조작하는 Playwright는 없습니다. 명령 하나는 180초까지이고, 연결한 폴더 안의 삭제(rm)는 막혀 있습니다.
- 이 폴더만으로 수업 자료 HTML을 다시 만들 수 있습니다. `수업자료/생성기`에서 `python3 -I build.py 2026.09`(회차 파일), `python3 -I build.py index`(전체 첫 화면)를 실행합니다. PC VM에서 다시 만든 결과가 `수업자료/완성본/`의 파일과 글자 하나까지 같음을 확인했고, 생성기 시험 61건도 통과했습니다(`python3 -I tests/test_build.py`).
- 자동 검사(`tools/qa_deck.js`, `tools/qa_index.js`)와 PDF 만들기(`tools/make_pdf.js`)에는 크롬이 필요합니다. Playwright와 Chromium이 있는 클라우드 세션으로 생성기 폴더, `수업자료/문항데이터`, `연계DB_통합_전체문항.csv`를 가져가 돌리고, 결과를 PC 폴더에 되돌려 저장합니다(매뉴얼 3.1절).
