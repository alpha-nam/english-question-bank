# 연계 분석 수업 자료 생성기

문항 데이터(JSON)와 틀(`template/`)을 합쳐, 회차마다 수업용 HTML 한 파일(문항 1개 = 장 5개)을 만든다.
장 5개는 시험 문항, 교재 원문항, 비교, 쉽게 보기, 교사 분석이다. 화면은 칠판 하나뿐이다.
같은 파일을 PDF로도 만든다. 공개 범위는 "전부 비공개"(2026-10-23 결정)라서 공개 주소는 만들지 않고, GitHub에도 아직 올리지 않는다(제이님 요청 2026-10-23).
문항은 늘 번호순으로 둔다(제이님 요청 2026-10-23).
연계 지도(회차 맨 앞의 45칸 한 장)는 회차마다 켜고 끄는 기능이다. 2026.09 는 제이님이 승인해서 켜 두었다(아래 "연계 지도").
여러 회차를 묶는 전체 첫 화면(`완성본/index.html`)도 같은 생성기가 만든다(아래 "전체 첫 화면").

## 폴더

```

                          index.css·index.js(전체 첫 화면, 회차 탭), skeleton_head.html·skeleton_tail.html(독립 파일 틀)
    tools/                qa_deck.js(회차 파일 자동 검사), qa_index.js(첫 화면 자동 검사), make_pdf.js(PDF),
                          skeleton.js(검사·PDF 도구가 쓰는 독립 파일 틀), extract_pilot.py(처음 데이터를 뽑은 1회용 도구)
    tests/                test_build.py, dom_identity.js, fit_report.js, qa_selftest.js, nav_click.js,
                          make_many.py(문항 9개짜리 가짜 회차), golden/(기준 결과물)
    백업/                 바꾸기 전 틀과 프로그램 사본 (헤더A적용전, 지도추가전, 표준모드전, 번호순·첫화면전)
  문항데이터/
    회차목록.json         전체 첫 화면의 제목과 회차 목록(탭 이름, 시험 이름, 시행 시기)
    _서식/                새 문항 서식(독해 지문형, 듣기 대본형, 도표)
    2026.09/              round.json, q03.json, q25.json, q31.json
```

## 쓰는 법

생성기 폴더에서 실행한다. 검사와 PDF는 Node와 Playwright(크롬)가 필요하다(Claude 작업 환경에는 있다).

| 하는 일 | 명령 |
|---|---|
| 데이터만 검사 | `python3 -I build.py 2026.09 --check` |
| HTML 만들기 | `python3 -I build.py 2026.09` (→ `완성본/<round.json의 out>`. 문서 형식 선언이 있는 독립 파일이라 더블클릭으로 열린다) |
| Artifact 에 올릴 조각으로 만들기 | `python3 -I build.py 2026.09 --fragment --out 경로` (문서 형식 선언·head·body 가 없는 조각. Artifact 가 틀을 씌운다) |
| 연계 지도를 넣어 만들기 | `python3 -I build.py 2026.09 --map` (`--no-map` 은 round.json 에 map 이 있어도 뺀다) |
| 자동 검사와 보고서 | `node tools/qa_deck.js ../완성본/2026.09_연계분석.html --out ../완성본/QA_2026.09_연계분석.md` |
| PDF 만들기 | `node tools/make_pdf.js ../완성본/2026.09_연계분석.html ../완성본/2026.09_연계분석.pdf` |
| 전체 첫 화면 만들기 | `python3 -I build.py index` (→ `완성본/index.html`. `--check`, `--fragment`, `--out 경로` 는 회차 파일과 같다) |
| 첫 화면 자동 검사 | `node tools/qa_index.js ../완성본/index.html --out ../완성본/QA_index.md` |
| 생성기 시험 | `python3 -I tests/test_build.py` (61건) |
| 검사기 시험 | `node tests/qa_selftest.js` (42건. 회차 파일 검사기 19건, 첫 화면 검사기 23건) |
| 이전·다음 문항 단추 시험 | `node tests/nav_click.js` (30건. 문항 9개짜리 가짜 회차를 지도 있는 것과 없는 것으로 만들어 PC·폰 폭 크롬에서 눌러 본다) |

### PC에서 Playwright 없이 쓰는 도구 (`tools/dev/`, 2026-10-26)

| 하는 일 | 명령 (연계DB 폴더에서) |
|---|---|
| 후보 문항 검사(정식 폴더를 건드리지 않음) | `python -X utf8 -I 수업자료/생성기/tools/dev/validate_cand.py --round=2026.06 [q01 q02 ...]` |
| 슬라이드 넘침·글자 크기·남는 높이를 숫자로 재기(PC 크롬 헤드리스) | `python -X utf8 -I 수업자료/생성기/tools/dev/measure_deck.py 2026.06 [창폭] [--cand]` |
| 쉽게 보기 장 카드 겹침 재기 | `python -X utf8 -I 수업자료/생성기/tools/dev/measure_deck.py 2026.06 1280 --easy` |

새 문항은 먼저 `문항데이터/_시안후보/<회차>/` 에 만들어 위 검사를 통과시키고, 그 뒤 `문항데이터/<회차>/` 로 옮겨 `build.py <회차>`, `build.py index` 를 돌린다.
틀(`template/`)을 고친 뒤에는 `tests/test_build.py --update-golden` 으로 기준 결과물을 새로 쓰고(바뀐 곳을 확인한 뒤에만) 시험 64건을 돌린다. 시험은 `tests/fixture/문항데이터/`(3문항 고정 사본)를 쓰므로 정식 문항이 늘어도 어긋나지 않는다.

자동 검사는 오류가 하나라도 있으면 종료 코드 1을 돌려준다. 오류 0건이 될 때까지 고친다.
주의는 눈으로 확인하고, 참고는 알려진 사항이다.

## 새 문항 넣기

1. `문항데이터/_서식/` 에서 맞는 서식(독해 지문형, 듣기 대본형, 도표)을 `문항데이터/<회차>/qNN.json` 으로 복사한다. NN은 시험 문항 번호(두 자리)다.
2. ★ 로 시작하는 안내 글을 모두 실제 내용으로 바꾼다. ★ 가 남아 있으면 만들기가 멈추고 남은 칸을 알려 준다.
3. 문항은 `q*.json` 을 번호순으로 모두 만든다(장 순서와 목차 순서). 일부만 만들려면 `round.json` 의 `order` 에 번호를 적되 번호순이어야 한다.
4. `--check` → 만들기 → 자동 검사 → PDF → 전체 첫 화면 다시 만들기(`build.py index`) 순서로 돌린다.

## 데이터 모양 (schema 1)

회차마다 `round.json` 하나와 문항마다 한 지문에 문항이 여러 개인 장문(43~45번)은 `q43.json` 하나만 만들고(제이님 요청 2026-10-26), 맡는 다른 번호를 `"covers": [44, 45]` 로 적는다. 효과: ① 머리글과 목차 줄에 `43~45번`으로 보인다 ② 지도에서 44·45번 칸도 눌리면 43번 장으로 간다(수업 자료 있음으로 센다) ③ DB 대조에서 44·45번이 같은 교재·쪽의 연계 문항인지 본다. 장에는 43번 문항(발문, 선택지, 정답)만 보이고 44·45번은 교사 분석에서 짚는다.

`qNN.json` 하나.

`round.json`

| 칸 | 뜻 |
|---|---|
| `id` | 회차 이름. 폴더 이름과 같게 (예: 2026.09) |
| `name` | 헤더 왼쪽에 보이는 시험 이름. 폭 때문에 짧게 쓴다 (예: 2027학년도 9월 모의평가, 수능은 2026학년도 수능) |
| `held` | 이름 밑의 작은 글 (예: 2026년 9월 시행) |
| `title`, `nav_title` | 브라우저 탭 이름, 맨 위 목차 줄 제목 |
| `order` | (선택) 만들 문항 번호(예: [3, 25, 31]). 번호가 작은 것부터 겹치지 않게 적어야 하고, 어기면 만들기가 멈춘다. 없으면 폴더의 `q*.json` 을 번호순으로 모두 만든다 |
| `out` | 만든 파일 이름 |
| `map` | `true` 이면 연계 지도 장을 맨 앞에 넣는다(선택. 없으면 넣지 않는다) |

`qNN.json`

| 칸 | 뜻 |
|---|---|
| `no`, `tag` | 시험 문항 번호, 목차에 쓸 짧은 이름(독해·듣기·도표) |
| `meta.exam` | `type` 문항 유형, `mode` 읽기/듣기, `answer` 정답(1~5) |
| `meta.book` | `name` 교재, `page` 쪽, `unit` 단원이나 회, `no` 교재 문항 번호, `type`, `answer` |
| `meta.link` | `label` 연계 방식, `felt` 학생체감 1~5 (교재를 공부한 학생이 시험 문항을 "본 적 있다"고 느끼기 쉬운 정도) |
| `text.exam`, `text.book` | 문항 원문(다시 친 것): `stem` 발문, `points` 배점(선택), `body`, `choices` |
| `text.quotes` | 비교 장에 보일 발췌: `exam`, `book` (글 목록) |
| `analysis.answer_note` | 정답 줄 옆 한 줄 설명 (`exam`, `book` 중 필요한 쪽만) |
| `analysis.compare` | `same`, `diff` (도표 문항은 `fig_labels` 도 필요) |
| `analysis.easy` | 쉬운 설명: `book`·`exam` 각각 `icon`, `text`, 그리고 `same`, `diff`, `sum` |
| `analysis.teacher` | `evidence`, `changed`, `view` (각각 글 목록) |

`body` 의 종류:

- `{"kind": "passage", "paragraphs": [{"t": 글, "fn": [각주, ...]}], "tight": true}` 지문. `tight` 는 긴 지문 장에서 글자를 조금 줄이는 표시. `"cols": 2` 는 안내문처럼 항목이 많은 지문을 2단으로 나누는 표시(문단은 단 사이에서 잘리지 않는다). 적지 않으면 지금까지와 같다.
- `{"kind": "speaker", "text": 대본}` 듣기 대본. `"cols": 2` 를 더하면 2단으로 나눈다(대화가 길 때).
- `{"kind": "figure", "side": "s1" 또는 "s2", "alt": 설명, "chart": 도표 설정, "passage": [...], "compact_override": {...}}` 도표. `s1` 은 도표가 왼쪽에 크게, `s2` 는 오른쪽 글이 크게. 도표 설정은 `title`, `series`, `groups`(`name`, `sub`, `v`), `ymax`, `axis`, `defs`, `note`, `hl`.

- `{"kind": "picture", "side": "s1"|"s2", "alt": 설명, "image": 파일명, "script": 대본}` 그림(2026-10-26). 그림 파일은 `문항데이터/<회차>/이미지/` 에 두고(PDF에서 뽑아 JPEG), HTML 안에 한 번만 담긴다. `script` 가 있으면 대본을 곁에 보인다.
- `{"kind": "table", "side": "s1"|"s2", "alt": 설명, "title": 제목, "head": [...], "rows": [[...]], "numbered": true, "hl": [강조할 행 번호], "script": 대본}` 표를 데이터로 다시 그린다(도표 문항).
- 비교 장의 `fig_labels` 는 양쪽이 모두 그림·표·도표일 때만 필수, 아니면 쓰지 않는다.

`choices`: `items` 5개, `lang` ("en"이면 영어 글꼴), `cols` 열 수.

공개 범위를 나중에 "분석만 공개"(B안)로 바꿀 수 있게, 지문 원문은 `text` 에, 우리가 쓴 분석은 `analysis` 에 나뉘어 있다.

## 글 표기

데이터의 모든 글에서 다음 표기를 쓴다. 이 밖의 `<`, `>`, `&` 는 그냥 글자로 취급한다.

| 쓰는 것 | 뜻 |
|---|---|
| `<mark>…</mark>` | 연계 단서(형광펜) |
| `<ev>…</ev>` | 정답 근거(물결 밑줄) |
| `<blank/>` | 빈칸 줄 |
| `<b>…</b>`, `<u>…</u>` | 굵게, 밑줄 |
| `<br>` | 줄바꿈 |
| `\|` | 뜻 덩어리 나누기(한국어 설명 글에서 줄이 바뀔 때는 덩어리 사이에서만 바뀌게 한다). 따옴표 안 영어 구와 굵은 영어 구는 저절로 한 덩어리가 된다 |

여는 표기와 닫는 표기의 짝이 맞지 않으면 만들기가 멈춘다.

## DB 대조 검사

만들기와 `--check` 는 문항 데이터(`meta.book.name`, `meta.book.page`, `meta.link.label`, `meta.link.felt`)를
`연계DB/연계DB_통합_전체문항.csv`(교재, 쪽, 연계방식, 학생체감)와 맞춰 본다. 다르면 어느 칸이 어떻게 다른지 알려 주고 멈춘다.
CSV에 그 문항이 연계가 아닌 것(비연계)으로 되어 있어도 멈춘다. CSV 파일이 없으면 이 검사는 건너뛴다(지도를 켠 경우는 CSV가 꼭 있어야 한다).
파일럿 때 31번 체감이 DB는 2점인데 데이터에는 1점으로 들어가 있던 것을 늦게 찾아서 만든 검사다.
DB가 맞고 데이터가 틀린 것으로 보고 데이터를 고친다. 반대로 DB를 고쳐야 하면 CSV를 먼저 고친 뒤 다시 돌린다.

## 연계 지도

회차 파일 맨 앞(`id="map"`)에 시험 문항 1~45번을 칸 하나씩 보여 주는 장을 넣는다(제이님 승인 2026-10-23, 21판부터 게시). 듣기 1~17번과 읽기 18~45번 두 줄로 나뉘고(폰은 한 줄 5칸),
칸마다 번호, 연계방식 약어, 교재 약어, 체감 네모 칸(현행 그대로)이 있다. 재료는 위의 CSV다.
켜는 법은 `round.json` 에 `"map": true` 를 적거나 `build.py <회차> --map` 이다(2026.09 는 켜 둠). 켜지 않으면 결과물이 지도 이전과 글자 하나까지 같다(기준 결과물과 같음을 시험이 지킨다).

| 칸 모양 | 뜻 |
|---|---|
| 주황 실선 테두리, 누르면 이동 | 수업 자료가 있는 연계 문항(`#qNN` 으로 이동) |
| 주황 점선 테두리 | 연계 문항이지만 수업 자료가 아직 없음(준비 중) |
| 흐린 칸, "독립" | 교재와 연계되지 않은 독립 출제 문항 |

- 맨 위 줄 숫자(교재 연계 N문항, 독립 출제 M문항, 수업 자료 K문항)와 아래쪽 연계방식 약어 풀이는 CSV에서 세어 만든다. 약어가 없는 연계방식이 CSV에 새로 생기면 만들기가 멈추니 `build.py` 의 `METHOD_TAG` 에 약어를 더한다.
- 문항이 8개를 넘는 회차는 위 목차 줄이 번호 알약 대신 `연계 지도 · ‹ 이전 문항 · 다음 문항 ›` 로 줄어든다(`COMPACT_NAV_OVER`). 단추는 `template/nav.js` 가 처리한다. 지금 보는 문항을 찾아 앞뒤 문항의 첫 장으로 옮기고, 맨 앞 문항에서 이전은 지도로 간다.
- `template/nav.css` 는 `.slide{scroll-margin-top:calc(var(--navh,58px) + 12px)}` 한 줄이고, `nav.js` 가 목차 줄 높이를 재어 `--navh` 로 넣는다. 폰에서 목차 줄이 두세 줄(96~110px)로 접혀도 이동한 장의 위쪽이 가려지지 않게 하는 것이다. 지도를 켰거나 문항이 8개를 넘는 회차에는 `nav.js` 와 함께 들어간다(지도 없이 문항만 많은 회차도 포함).
- 문항이 8개 이하이고 지도도 켜지 않은 결과물에는 이 보정이 없어서, 폰 폭(390·360)에서 목차 링크로 이동하면 장 위쪽이 목차 줄에 가려진다(지도를 켜기 전의 20판이 이 경우였다). 자동 검사가 이를 "주의"로 알려 준다(보정이 들어간 덱에서는 같은 검사가 "오류"가 된다).
- 자동 검사는 지도 장을 5장 묶음 검사에서 빼고, 칸 45개, 머리 줄 숫자와 칸 일치, 눌리는 칸이 가리키는 곳, 문항마다 눌리는 칸 하나, 칸 안 글자 넘침, 범례가 장 안에 있는지를 따로 본다.
- 지도 칸 모양과 숫자 계산은 전체 첫 화면과 같은 코드(`map_slide`)를 쓴다.

## 전체 첫 화면 (index)

`완성본/index.html` 한 파일: 회차 탭 8개, 탭마다 같은 모양의 연계 지도 한 장, 수업 자료 열기와 PDF 받기 단추. 지도는 CSV 에서 바로 만들어서 수업 자료를 아직 안 만든 회차도 지도는 보인다(칸은 점선 "준비 중").
수업 자료가 있는 회차(탭에 "자료 있음" 표시)는 지도의 주황 실선 칸을 누르면 그 회차 파일의 해당 문항(`2026.09_연계분석.html#q31`)으로 간다. 링크는 같은 폴더(`완성본/`) 기준 상대 주소라서 폴더째 옮겨도 된다.

- 재료는 `문항데이터/회차목록.json`(제목, 부제, 회차마다 `id`·`tab`·`name`·`held`)과 CSV 다. 회차를 늘릴 때는 목록에 한 줄을 더한다. `name`, `held` 는 `round.json` 과 같아야 한다(다르면 만들기가 멈춘다).
- 탭은 최근 회차가 왼쪽이다(제이님 요청 2026-10-23). 파일 순서와 상관없이 `id` 내림차순으로 정렬하고, 맨 왼쪽(가장 최근) 탭이 처음에 열려 있다. 주소 끝에 `#2026.09` 처럼 회차 이름을 붙이면 그 탭이 열린다.
- 탭이 어떤 회차에 수업 자료가 있다고 보는 기준은 두 가지다. `문항데이터/<회차>/` 가 있고 `완성본/` 에 그 회차 HTML 이 만들어져 있어야 한다. 눌리는 칸은 그 폴더의 `qNN.json` 문항이다. PDF 단추는 같은 이름의 `.pdf` 가 있을 때만 켜진다(없으면 "PDF 준비 중").
- 새 문항을 만들거나 회차 파일을 다시 만든 뒤에는 첫 화면도 다시 만든다(`build.py index`). 첫 화면 검사는 눌리는 칸이 가리키는 문항이 덱 파일에 정말 있는지, 덱 파일의 문항이 모두 지도에서 눌리는지 확인한다.
- 탭은 키보드로도 쓴다(Tab 으로 탭 줄에 들어가 ← → Home End 로 옮김). 구현은 `template/index.js`.
- 첫 화면은 8회 지도가 모두 들어 있어도 약 143KB 다(아이콘은 `link` 하나만 넣는다, `icons_subset`).
- 자동 검사(`tools/qa_index.js`)는 폭 6가지에서 탭을 하나씩 눌러 보며 탭 구조와 순서, 지도 45칸, 머리 줄과 칩 숫자, 열기·PDF 단추, 칸 글자 넘침, 폰 가로 넘침을 보고, 폭 1300 에서 링크가 가리키는 파일과 문항, 탭 누르기·화살표 키·주소 끝 회차 동작을 본다.
- 첫 화면에서 회차 파일로 갈 수는 있지만 회차 파일에서 첫 화면으로 돌아오는 링크는 아직 없다(Artifact 한 파일일 때는 갈 곳이 없어서 보류).

## 독립 파일과 Artifact 조각 (문서 형식 선언)

Artifact 는 올린 조각에 문서 형식 선언(`<!doctype html>`), charset, viewport, 작은 초기값을 씌워 표준 모드로 보여 준다. 조각을 파일로 그냥 열면 크롬이 괴상 모드(quirks)로 읽어서 화면 배치가 다르다(2026-10-23 발견: 같은 덱에서 칸 441개의 자리가 달랐고 25번 비교 장 헤더 여유가 5~9px 달랐다).
그래서 지금은 다음처럼 한다.

- `build.py` 기본 결과물은 같은 틀(`template/skeleton_head.html`, `skeleton_tail.html`)을 씌운 독립 파일이다(폴더째 나눠 주고 더블클릭으로 열 때 Artifact 화면과 같다). Artifact 에 올릴 때는 `--fragment` 로 조각을 만든다.
- 검사, PDF, 화면 시험 도구는 모두 `tools/skeleton.js` 로 같은 틀을 씌워 연다(`prepared(파일)`: 이미 문서 형식 선언이 있으면 그대로). `qa_deck.js`, `qa_index.js` 는 표준 모드가 아니면 오류를 낸다.
- 이 발견 전에 측정한 검사·PDF 결과(21판까지)는 괴상 모드로 읽은 것이었다. 22판부터는 표준 모드 결과다(오류는 그때도 지금도 0건).
- 헤더 폭 검사는 1px 까지의 반올림 오차를 오류로 보지 않는다. 헤더 칸 사이 간격은 `.8cqw` 다(1cqw 에서 줄임, 눈에 띄는 바뀜 없음).

## 틀을 고칠 때

`template/` 의 글은 18판 시안에서 그대로 떼어 온 것이다. 고치면 모든 회차에 퍼진다.

1. 고치기 전에 `백업/` 에 사본을 둔다.
2. 고친 뒤 `python3 -I tests/test_build.py` 를 돌려 바뀐 곳이 의도한 곳뿐인지 본다. 일부러 바꾼 것이면 눈으로 확인한 뒤 `--update-golden` 으로 기준을 새로 쓴다.
3. 화면이 어떻게 달라졌는지는 `node tests/dom_identity.js 옛.html 새.html` (칸 자리·크기), `node tests/fit_report.js 옛.html 새.html` (자동 맞춤 배율)로 본다.
4. `node tools/qa_deck.js` 오류 0건, `node tests/qa_selftest.js` 통과. 지도나 목차 줄을 건드렸으면 `node tests/nav_click.js` 도 돌린다. 첫 화면 틀(`index.css`, `index.js`, `map.css`)을 건드렸으면 `build.py index` 로 다시 만들고 `node tools/qa_index.js` 오류 0건을 본다.
5. 보이는 바뀜은 제이님이 시안으로 확인한 뒤에 적용한다.

헤더 오른쪽(`.kd`) 두 줄의 높이는 시험·교재 칸 높이를 넘지 않게 맞춘 값이다(줄 간격 1.25 + 알약). 넘으면 헤더가 높아져 본문 글자가 줄어든다.

## 알려진 한계와 다음 단계

- 폰에서 도표 안 글자가 6.5~9px로 작다(매뉴얼 8장 21번, 제이님 결정 대기).
