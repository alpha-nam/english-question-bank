# 영어 문제은행(가칭) 청사진

작성 2026-10-28, 제이님과 대화로 합의한 내용(초안). 지금 상태는 `진행상황.md`가 기준이고, 이 문서는 앞으로 만들 것의 설계입니다.

## 1. 목표

최근 10년치 3학년 영어 모의평가·수능 기출을 문항 DB로 만들고, 연계 분석(지금 만든 것)과 이어서 ① 문항 고르기와 모의고사 조립·인쇄 ② 원문항을 새 문항으로 바꾸는 변형(상·중·하) ③ 유형별 모의고사 만들기를 하는 개인용 프로그램을 만든다. 나중에 1·2학년(교육청 학평)을 더한다. 참고 모델은 제이님이 쓰시는 수학용 화면(연계 출제 스튜디오, 기출 문제은행).

## 2. 정해진 것

- 범위: 최근 10년(2017~2026). 20년은 하지 않는다.
- 사용자: 지금은 제이님 혼자. 나중에 같은 영어과 선생님들께 공유할 수 있다.
- 변형 문항의 용도: 수업 자료.
- 6·9·11월(수능)은 학년도 기준이 다르다(시행 연도 + 1). 시행 연도와 학년도를 모두 칸으로 둔다.
- GitHub에는 올리지 않는다. 공개 범위는 전부 비공개(2026-10-23 결정).
- 처음에는 DB를 프로그램에 모두 넣은 개인용으로 만든다. 배포용은 같은 코드로 DB를 뺀 버전을 따로 낸다(비밀번호는 보호가 못 되므로 쓰지 않는다).

## 3. 5단 구조

1. **기출 DB**: 문항 하나가 파일 하나. 칸: 문항 ID, 시행연도, 학년도, 시험(월), 학년, 출제 기관, 번호, 유형, 정답, 배점, 지문, 듣기 대본, 이미지, 공유 표시(공유 가능/비공개).
2. **연계 DB**: 지금 만든 분석(CSV 338행)을 문항 ID로 기출과 이어 준다.
3. **변형 스튜디오**: 4장.
4. **모의고사 조립**: 유형, 난이도, 연계 여부로 골라 담고 시험지·정답지를 인쇄(PDF).
5. **1·2학년 확장**: 메타 칸에 출제 기관과 학년을 처음부터 넣어 두고 데이터만 더한다.

### 3.1 내 문항 가져오기 (제이님 추가 요청 2026-10-28)
기출이 아닌, 앞으로 수업할 문제(사설, 교재, 하프모의고사 등)를 캡처해서 이미지로 붙여넣으면 DB 문항으로 만든다.
- 흐름: 이미지 붙여넣기 → 글자와 선택지 읽기(OCR, 비전) → 유형 판별 → 제이님이 확인·교정 → "내 문항" DB 저장(출처 칸: 직접 입력, 공유 표시 기본값은 비공개).
- 만들어 주는 것: 빈칸·순서·삽입 등 유형별 해설 화면(분석 카드), 하프모의고사 해설, 학습지(A4 2쪽 학생용과 교사용 정답지).
- 기존 도구 재사용: 지문 분석 카드와 학습지 만들기는 제이님이 이미 쓰는 기능(지문 카드, 학습지 만들기)과 같은 형식으로 잇는다.
- 읽기 오류가 정답을 바꿀 수 있으므로 저장 전에 제이님 확인 단계를 둔다.

## 4. 변형 스튜디오 (가장 중요한 부분)

AI가 수능 출제 방향과 다르거나 엉뚱한 단어만으로 문제를 만든 경험이 가장 큰 걱정이므로, "기준을 먼저 세우고 그다음에 만든다".

### 한 문항을 만드는 순서
1. 원문항 분석: 정답 근거 문장, 핵심 개념, 오답이 유혹하는 방식을 먼저 뽑는다.
2. 바꿀 것 정하기: 난이도별로 바꾸는 항목이 정해져 있다.
   - 하: 표현·어휘를 쉽게. 구조는 그대로.
   - 중: 선택지와 오답 구조를 바꾼다.
   - 상: 단서를 흩어 놓거나 추론 단계를 늘린다.
   - 금지: 단어만 바꿔 어렵게 보이게 하기. 소재와 주제를 바꾸기.
3. 본보기 붙이기: 같은 유형에서 평가원이 실제로 교재를 바꾼 사례(연계 분석의 191쌍과 "바뀐 점")를 실물로 보여 준다.
4. 만들기: 지문, 선택지, 정답, 정답 근거를 한꺼번에. 근거 없는 정답은 허용하지 않는다.
5. 자동 점검: 다른 AI가 정답을 모르는 채로 풀어 정답이 같은지, 오답이 정답처럼 읽히지 않는지 본다. 지문 어휘 수준도 기출과 비교한다.
6. 제이님 검수: 통과한 것만 보고 승인하거나 고친다. 고친 내용은 기록해 다음에 반영한다.

### 분석 범위와 DB 범위 (2026-10-28)
DB(이미지, 검색)는 최근 10년. 분석(규격표)은 DB 10년을 기본으로 하고, 그 이전 10년은 글자만 넣어 유형별 경향 확인에 쓴다(영어는 2018학년도 수능부터 절대평가 등 형식이 바뀌어, 규격표에 시기 표시를 달고 변형 기준은 현행 형식으로 한다). "학습"은 AI 훈련이 아니라 기출 분석으로 규격표와 본보기를 만드는 일이다. 평가원 공개 자료(출제 방향 등)가 무엇이 있는지는 아직 확인하지 못했고 먼저 찾아본다.

### 유형별 출제 규격표
10년치 기출을 유형별로 분석해 규격표를 만든다(빈칸 추론: 단서 문장 위치, 정답의 추상화 수준, 오답 유형 등). 새 문항은 규격을 어기면 통과하지 못한다. 유형마다 규칙이 다르므로 한 유형씩 만든다.

### 난이도 기준
기출의 문항 번호 위치와 연계 분석의 학생 체감을 참고하고, 상·중·하가 무엇을 바꾸는지로 정의한다.

### 시범 검증
처음에는 유형 2~3개만 만든다. 진짜 기출과 새 문항을 섞어 제이님께 보여 드려 구분되는지 본다. 구분되면 규격을 고치고, 통과하면 확대한다.

## 5. 프로그램과 AI 연결

- 프로그램으로 만드는 것: 검색, 골라 담기, 조립, 인쇄, 연계 분석 보기. API 없이 PC에서 돈다. 지금 만든 생성기를 재사용한다.
- API가 필요한 것: 변형 만들기, 자동 점검. 어느 AI든 바꿔 끼울 수 있는 한 통로로 만든다. 기본은 Gemini 후보, Claude 등으로 교체 가능. 만드는 AI와 점검하는 AI를 다르게 두면 점검이 더 믿을 만하다.
- 확인할 것(제이님): 학교 계정으로 Google AI Studio에서 API 키를 만들 수 있는지. 교육청의 Gemini 구독과 API는 별개일 수 있다. 무료 한도와 입력 내용 이용 조건은 아직 확인하지 못했다.
- API 키는 파일·화면에 남기지 않고 PC 환경 설정에만 둔다.
- 순서: API 없이 1단계를 먼저 만들고, 변형은 시범으로 품질을 확인한 뒤에 API 버튼으로 옮긴다.

## 6. 폴더 구조와 공유

- 프로그램 폴더(화면, 검색, 조립, 인쇄, 변형)와 DB 폴더(기출, 교재, 연계 분석)를 분리한다. 혼자 쓰는 동안은 한 위치에 둔다.
- 개인용: DB 전부 포함. 배포용: 같은 코드로 DB 없이 빌드. 선생님들은 각자 원본 PDF를 넣어 자기 DB를 만든다.
- 문항마다 공유 표시(공유 가능/비공개)를 둔다. 원문이 들어간 파일에는 "수업용, 배포 금지"를 표시한다.
- 공유 단계: 1 혼자(지금), 2 같은 학교 영어과(비공개 공유), 3 공개 배포(한국저작권위원회 상담 뒤 결정). 저작권 판단은 전문가 확인이 필요하다.

## 7. 첫 작업 순서

1. 10년치 원본 파일을 모으고 형식(글자 PDF/스캔본)을 확인한다(제이님이 찾아 주기로 함). 지금 `기출/`에는 2022.06~2026.09 14회분이 있다.
2. 문항 ID 규칙과 DB 칸을 정한다.
3. 문항 분리 프로그램을 만들어 기출 DB를 만든다. 문항 수와 정답을 공식 정답표와 전수 대조한다.
4. 연계 DB를 문항 ID로 잇는다.
5. 검색·골라 담기 화면(개인용)을 만든다.
6. 유형 2~3개의 출제 규격표를 만들고 변형 시범을 한다.
7. 통과하면 유형을 넓히고, 조립·인쇄, API 버튼, 1·2학년을 차례로 더한다.

## 8. 열린 질문

- 10년치 원본 파일의 위치와 형식.
- 학교 계정으로 Gemini API 키를 만들 수 있는지.
- 처음 시범으로 삼을 유형 2~3개(추천: 빈칸 추론, 순서 배열, 문장 삽입 중에서).
- 화면 형태: PC 프로그램(설치형)과 브라우저에서 여는 화면 중 무엇이 편한지(추천: 브라우저에서 여는 화면. 지금의 HTML 틀과 가장 잘 맞는다).
